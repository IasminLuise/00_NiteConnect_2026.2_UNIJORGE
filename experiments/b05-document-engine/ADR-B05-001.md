# ADR-B05-001 — motor documental: evidência inicial, decisão pendente

Data: 17/10/2026. Base: `e64340835d9a5a8c013cfee8c0ffac49c5054ff0`.
Estado: **NO-GO para os dois modelos oficiais nos candidatos ensaiados; G1 não aprovado**.

## Decisão atual

Manter Collabora CODE como candidato em avaliação. A execução sintética mostrou
edição/salvamento WOPI e conversão no mesmo motor, sem justificar um LibreOffice
separado no produto. Não aprovar integração definitiva, V6, fornecedor de storage,
edição de produção ou implantação institucional a partir destes resultados.
O comparador permanece somente no experimento. Não há assinatura/aceite editorial.

Ensaio controlado posterior: `results/2026-10-17-fidelity-decision.md`. ONLYOFFICE
Community 10.0.0.1 foi comparado em laboratório separado: melhora paginação e
preservação do corpo, mas regrava SAVEDATE como REF. CODE mantém divergência no
relatório e falha no formato de SAVEDATE. Nenhum motor aprovado para o conjunto.
O logotipo reapareceu em todas as páginas nas reexportações controladas; a falha
histórica de visibilidade não foi atribuída definitivamente ao motor.

## Ambiente fixado

- Windows/PowerShell + Docker Desktop Linux; VM Docker: 8 CPUs e 8.258.818.048 bytes.
- Java 21 / Spring Boot 4.1.1, sem novas dependências na API principal.
- CODE imagem 26.04.5.1.1; label do motor 26.04.5.1; digest amd64
  `sha256:56541aad09403975646dfb87a3716e38afecce09b5f853391eb6d937a0ccd402`.
- Java runtime, Debian e Nginx fixados por digest no Compose/Dockerfiles.
- LibreOffice Writer/Math Debian `4:7.4.7-1+deb12u14`; fontes DejaVu `2.37-6`
  e Liberation2 `2.1.5-1`. Manifesto transitivo dentro da imagem.
- CODE inclui fontes Liberation Serif e DejaVu Sans usadas nas fixtures.
  Inventário local de 329 arquivos de fontes com hashes em `results/generated/fonts-code.json`.
- Chromium local 153.0.8010.12; emulação Android Pixel 7 com viewport 390×844.
  Emulação não demonstra funcionamento em Android físico, Safari ou iOS.

## Resultados observados

1. Health do host e discovery responderam HTTP 200. CODE saudável; processamento
   isolado da aplicação principal. Portas somente em 127.0.0.1.
2. F01–F09 originais converteram nos dois motores: 18 PDFs válidos. Mesmas contagens
   de páginas: `1, 1, 3, 1, 1, 1, 1, 1, 40`. Não é comparação com Microsoft Word.
3. Texto extraído foi equivalente após remoção de whitespace em 8/9 pares. F05
   diferiu pela ordem de extração do número de rodapé; renderização inspecionada
   mostrou o número e o restante do conteúdo nos dois motores. Não houve perda
   demonstrada nesse caso. Isso não prova igualdade visual de todos os elementos.
4. F01 abriu no navegador; três ciclos adicionaram B05-CICLO-1/2/3. Os três
   marcadores foram confirmados no XML do DOCX baixado do host. Ao final do terceiro
   ciclo havia quatro versões naquele instante. Versões anteriores permaneceram.
5. Duas sessões sintéticas editaram pontos distintos em paralelo. O DOCX persistido
   contém B05-COEDIT-A e B05-COEDIT-B, além dos três ciclos. Essa é evidência básica,
   não ensaio de carga nem validação de revogação de colaborador durante coedição.
6. Após reiniciar CODE, F01 foi reaberto e renderizado com todos os cinco marcadores.
   Elimina a dependência exclusiva de cópia em memória do motor nessa verificação.
7. Sessão de leitura exibiu modo somente leitura e PutFile retornou 403. Download
   de sessão válida retornou 200; após revogação pelo navegador retornou 401.
   Token de F01 usado para outro documento retornou 404; DOCX inválido em PutFile 415.
8. F09 abriu e salvou B05-LONGO, confirmado nos bytes recuperados do host.
   A primeira superfície canvas apareceu em 1.361 ms nessa amostra; isso não mede
   tempo até documento completamente pronto, portanto não é SLA/benchmark de abertura.
9. Wrapper mobile recebeu viewport explícito. Leitura renderizada conferida em
   emulação Chromium/Android 390×844; captura local. Edição/touch/teclado em dispositivo
   físico, acessibilidade e outros navegadores continuam pendentes.
10. Gateway negou conversão direta de DOCX válido com 403. Com CODE parado, conversão
    pelo host retornou 503; SHA-256 do DOCX permaneceu igual. CODE foi reiniciado.
    Caso cobre indisponibilidade; timeout lento induzido ainda não foi executado.
11. Probe de logs Docker encontrou zero padrões de capacidades WOPI em claro.
    Escopo: logs dessa execução; não equivale a auditoria exaustiva de temporários,
    heap, dumps, observabilidade de produção ou tráfego de rede.

Os JSONs por execução registram versões/hashes e os tempos observados. PDFs editados
também são comparados usando os mesmos bytes de origem nos dois motores. Medições
interrompidas não são consideradas execuções completas. Artefatos binários são ignorados.

## Amostras de desempenho

Na primeira rodada, Collabora levou 2,169–2,716 s por conversão; LibreOffice
3,515–5,239 s incluindo inicialização do contêiner. Fontes, versões, perfil e
topologia diferem; não concluir superioridade do motor só desses tempos.

Após conversões, amostra pontual: CODE 531,1 MiB, Java 138,8 MiB, gateway 2,418 MiB.
Com dois documentos abertos (um deles F09), CODE 765,1 MiB, Java 139,5 MiB,
gateway 2,75 MiB; CPU pontual CODE 1,95%, Java 0,16%, gateway 0,12%.
Não são picos, percentis, capacidade máxima, memória por usuário ou custo institucional.
Limites aplicados: CODE 3 GiB/2 CPUs, Java 512 MiB/1 CPU, LO 1 GiB/1 CPU.

`results/2026-10-17-conversions.json`, `results/2026-10-17-visual-comparison.json`

## Correções encontradas durante a execução/revisão

- Bridge internal não publicou portas no Docker Desktop usado: bridge dedicada e
  loopback explícito; não declarar isolamento de egress.
- Allowlist do CODE aceitou conversão direta via loopback: Nginx agora é a única
  entrada publicada e bloqueia a rota de conversão.
- Formulário enviava origem incompatível por Referrer-Policy: página inicial usa
  same-origin; editor/WOPI mantêm no-referrer. Regressão reproduzida antes da correção.
- Precisão/formatação de timestamp: CAS compara instantes com resolução micros,
  com avanço monotônico; regressões para formatos equivalentes e relógio com nanos.
- ZIP sem central directory era aceito por ZipInputStream: validar EOCD/diretório
  central/CRC e limitar entradas mesmo vazias. Regressões reproduzidas antes dos ajustes.
- Medição LO podia reutilizar PDF antigo: arquivo exclusivo por versão/execução e
  regressão com ferramenta retornando zero sem gerar PDF novo.
- Linux UID/volumes: wrapper passa UID/GID do usuário comum; validar no CI remoto.
- Viewport ausente no HTML do editor: corrigido e conferido em emulação mobile.
- Relatório oficial continha hyperlinks HTTPS inertes, recusados pelo validador.
  Exceção limitada ao tipo hyperlink, HTTPS/host válido/sem credenciais; nenhum
  acesso ao destino pelo host. Imagens e demais relações externas seguem negadas.
  Regressões e suíte do host: 25 testes aprovados.

Ensaio oficial completo e seus limites em `results/2026-10-17-official-models.md`.
Fontes e evidências privadas permanecem ignoradas; não entram no corpus sintético.
Complemento em `results/2026-10-17-av3-and-fidelity.md`: Calibri disponível não
resolveu a paginação do relatório; AV3 salvou o corpo, mas regravou SAVEDATE com
erro no Word e alterou a visibilidade do logotipo. Contagem de páginas não é nota
percentual de fidelidade. G1 continua pendente.

## Pendências que bloqueiam GO

Completar modelos reais autorizados e aceite editorial; resolver divergência de
layout do relatório já ensaiado; inventário de arquivos/fontes;
completar matriz, inclusive revogação durante coedição e recuperações; TLS/WSS;
isolamento/egress, quotas/retention, backup/restauração; ensaios de recursos e
carga-alvo; licença/suporte de produção e aprovação responsável. CODE continua
somente candidato de desenvolvimento. Ausência de evidência não é NO-GO técnico,
mas também não permite GO nem GO com ressalvas.

## Adendo B05.0.1 — 17/10/2026, pesquisa focal

Este adendo preserva a decisão e os resultados B05.0 acima. Base da pesquisa nova:
`360fc24`, PR #9 aberto; branch derivada `spike/b05-compatibilidade-docx`.

**Decisão técnica mantida: NO-GO para edição integrada dos dois modelos nas versões
ensaiadas. G1-F reprovado, G1 não aprovado, G2 não aberto/aprovado.** Nenhuma alteração
no produto ou modelo oficial e nenhum editor/versão corretiva aprovado.

Há evidência nova: ONLYOFFICE perde SAVEDATE simples já na representação carregada;
campo complexo sintético preserva instrução e atualiza no Word. CODE tem reprodução
fonte-livre da máscara inválida após save, com visualização C0 diferente do AV3.
Uma tabela mínima reproduz a redução de tamanho herdado a 10 pt e de paginação.
No relatório, alterar apenas tamanhos numa cópia diagnóstica recupera as fronteiras
de todos os parágrafos Word; essa cópia não foi adotada como correção.

Não foi identificada versão/patch pertinente para novo A/B; nenhuma imagem diferente
foi instalada. Reproduções e relatos foram preparados, sem envio. Não se incluiu
reparo de XML no caminho de salvamento. Mantém-se prioridade de correção nativa
do campo simples no ONLYOFFICE; qualquer solução precisa passar fixtures focais
e depois os modelos completos antes de reconsiderar G1-F.

Microsoft 365 foi avaliado documentalmente: CSPP não é direito de cliente comum;
catálogo NITE + storage SharePoint depende de autorização/licenças e PoC próprias.
Nenhuma rota foi ativada ou aprovada. Edição externa mudaria o requisito e exige
decisão expressa de escopo. Responsável institucional pelos modelos/tenant e aceite
editorial ainda pendentes; não há assinatura presumida.

## Adendo B05.0.2 — adaptador limitado e parada no Gate C

17/10/2026. A nova autorização permitiu testar uma transformação **pré-edição**
de SAVEDATE simples para complexo em cópias elegíveis por hash/version. Não revoga
ou reescreve os resultados B05.0/B05.0.1; não autoriza reparo depois do save.

Adaptador e controles sintéticos demonstraram preservação de campo no Word,
partes não tocadas e idempotência. Foi acrescentada porta opt-in de validação ao
host experimental, roteiro independente, recusa antes do commit e quarentena privada.
Nenhum modelo oficial foi normalizado: o Gate C não passou.

No navegador, “All changes saved” apareceu sem versão nova no host. O PutFile
posterior foi recusado por alterações estruturais não certificadas; reabrir mostrou
aviso de backup ainda não salvo no storage, com os dados do ensaio presentes.
Isso não comprova perda definitiva ou corrupção das mudanças reserializadas.
Também não prova o contrato de confirmação/recuperação exigido. Não se afrouxou
a política aprendendo a saída do motor. C1/C2 oficiais e E não foram executados.

**NO-GO-F do fluxo experimental; equivalência da variante nos modelos oficiais
INCONCLUSIVA.** G1 continua não aprovado e G2 fechado. Não integrar o protótipo,
implementar V6 ou modificar modelos por inércia.

Recomendação expressa: submeter PoC sintética Microsoft 365/SharePoint à autoridade
institucional, preservando a preferência por modelos intactos. Tenant/licenças,
storage/retention, ACL/Graph e experiência de edição precisam de autorização e
prova próprias; não há direito presumido ao CSPP/iframe. Se isso for inviável,
decidir formalmente novas versões dos modelos com aceite editorial. Nenhuma rota
foi implantada/contratada ou autorizada automaticamente por este adendo.
